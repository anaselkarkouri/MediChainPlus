# MediChain+ — Fabric Chaincodes & IPFS Module

**Owner:** Anas El Karkouri  
**Scope:** Hyperledger Fabric 2.5 chaincodes, CouchDB indexes, IPFS encrypted storage helper, and handoff details for Omar Gaga's Node.js API Gateway.

This repository implements the private-blockchain part of MediChain+:

- `patient-registry`: stores patient identity metadata and consent references on Fabric.
- `medical-record`: stores medical record metadata, IPFS CIDs, SHA-256 file hashes, and claim links.
- `prescription`: stores doctor prescriptions, medication list metadata, hashes/signature references, and dispensing status.
- `ipfs-module`: uploads/retrieves encrypted files through IPFS Kubo, calculates SHA-256 hashes, and pins CIDs.

Large medical files are **not** stored on Fabric. Fabric stores immutable metadata, integrity hashes, access policies, and IPFS CIDs only.

## 1. Prerequisites

Recommended versions:

- Node.js 18+
- npm 9+
- Docker 24+
- Docker Compose v2
- Hyperledger Fabric binaries 2.5.x: `peer`, `configtxgen`, `fabric-ca-client`
- Fabric samples, recommended for the fastest MVP demo: `fabric-samples/test-network`

## 2. Installation

```bash
npm install
npm run build
npm test
```

## 3. Fast MVP network using Fabric test-network

Set the path to your local Fabric samples:

```bash
export FABRIC_SAMPLES_PATH=$HOME/fabric-samples
./scripts/network.sh up
./scripts/createChannel.sh
./scripts/deployChaincodes.sh
```

This starts Fabric with CouchDB, creates channel `medichannel`, starts IPFS Kubo, and deploys the three chaincodes.

## 4. Strict 1-org / 2-peer architecture

The folder `network/one-org-two-peers/` contains a Docker Compose architecture matching the project assignment: one organization, two peers, one orderer, one CA, two CouchDB instances, and one IPFS Kubo node.

For academic demonstration, the scripts default to `fabric-samples/test-network` because it is the most reliable and fastest way to get a working local Fabric deployment. The chaincode package names, function names, events, payloads, and CouchDB indexes remain the same in both deployments.

## 7. Security model

- No raw CIN/national ID on-chain: store `nationalIdHash` / `identityHash` only.
- No medical files on Fabric: only `ipfsCid`, `fileHashSHA256`, encryption metadata and access policy.
- IPFS content must be encrypted before upload with AES-256-GCM or equivalent.
- Every write emits a Fabric event for audit and backend listeners.
- CouchDB rich queries use `objectType` selectors and indexes.
- Prescription content is immutable; status can change through controlled functions only.
- Chaincodes check X.509 `role` / `roles` attributes when Fabric provides them. The API service identity should be enrolled with an allowed role, usually `admin`, while end-user authorization is enforced at the API JWT layer.

## 9. Troubleshooting

**Chaincode deployment fails with package not found**  
Run `npm install && npm run build` before `deployChaincodes.sh`.

**CouchDB query returns empty list**  
Check that payloads include `objectType` internally. The chaincodes set this automatically for new records.

**IPFS upload fails**  
Check IPFS is running:

```bash
curl http://127.0.0.1:5001/api/v0/version -X POST
```

**Fabric identity errors**  
Use the admin identity generated by `fabric-samples/test-network` or enroll a user through Fabric CA before calling from Gaga's backend.
